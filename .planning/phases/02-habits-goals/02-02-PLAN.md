<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Confirmation dialog → mutation controller | A user decision gates an irreversible or state-changing API call. |
| Controller → authenticated API | Pause, complete and delete cross the bearer-authenticated client/server boundary. |
| API response → rendered list/detail | Untrusted success/error responses determine whether visible state may change. |
| Dependency branch → stacked PR | Incorrect base selection can duplicate HBM-10 or hide HBM-11 scope. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Repudiation | Lifecycle dialogs | mitigate | Require an explicit, action-specific confirmation and cover both cancel and confirm paths in widget tests. |
| T-02-07 | Tampering | Pause date payload | mitigate | Validate required start date and optional end date ordering before serialization; backend retains state invariants. |
| T-02-08 | Elevation of Privilege | Lifecycle endpoints | mitigate | Use the shared bearer Dio client, resource ids returned by authenticated lists, and server authorization; never send usuarioId. |
| T-02-09 | Tampering | Delete UI state | mitigate | Remove list/detail state only after 204; on 404/409/network failure retain the entity and expose retryable feedback. |
| T-02-10 | Denial of Service | Repeated mutation taps | mitigate | Disable all lifecycle controls while a mutation is in flight and process one confirmation result once. |
| T-02-SC | Tampering | npm/pub supply chain | mitigate | Add no packages or lockfile changes; execute only the existing audited toolchain. |
</threat_model>
