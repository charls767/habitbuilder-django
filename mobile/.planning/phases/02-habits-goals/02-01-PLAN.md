<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated Flutter client → HabitBuilder API | Bearer-authenticated requests cross into a server that owns authorization and tenant isolation. |
| API JSON → DTO/domain | Untrusted response and error payloads are parsed into typed mobile state. |
| Form input → request payload | User-controlled strings, dates and frequency parameters become JSON. |
| Dirty worktree → ticket branch | Concurrent and historical changes can contaminate the HBM-10 diff. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing / Elevation | Habit list/detail/data source | mitigate | Use the shared authenticated Dio client and server-owned `/habits` resources; never accept or synthesize a user id or treat client filtering as authorization. |
| T-02-02 | Tampering | Frequency and habit payloads | mitigate | Validate the exact discriminator variants, ranges, unique weekdays and contract fields before request serialization. |
| T-02-03 | Information Disclosure | `ApiException` and UI errors | mitigate | Surface actionable contract messages/field errors without tokens, raw Dio objects, foreign resource details or request headers. |
| T-02-04 | Denial of Service | Create/update controls | mitigate | Disable duplicate submits while mutation state is loading and invalidate providers only once after success. |
| T-02-05 | Tampering | Git branch and safety stash | mitigate | Snapshot the dirty tree, preserve other owners' diffs, compare against `origin/main`, and never apply/pop/drop `stash@{0}`. |
| T-02-SC | Tampering | npm/pub supply chain | mitigate | Add no packages; keep `pubspec.lock` and `package-lock.json` unchanged and use the already-audited Flutter/Prism toolchain. |
</threat_model>
