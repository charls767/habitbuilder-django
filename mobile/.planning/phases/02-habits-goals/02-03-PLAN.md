<interfaces>
Canonical goal operations:
- GET/POST `/goals`
- GET/PATCH `/goals/{goalId}`
- PUT/DELETE `/goals/{goalId}/habits/{habitId}`

Domain contracts:
- `MetaEstado` maps `en_progreso`, `lograda`, `pausada`, `cancelada`; the
  user-facing label for `lograda` is `Alcanzada` per GOAL-03.
- `Meta` contains id, nombre, descripcion, fechaObjetivo, estado and
  `List&lt;String&gt; habitoIds`. It deliberately has no percentage, metric,
  chart input or other derived field per D-07.
- `GoalRepository` exposes list/get/create/update plus `linkHabit` and
  `unlinkHabit`. Goal deletion is not part of HBM-12.
- `HabitRepository.listHabits` and `Habito.metaId` from 02-01 are reused for
  linking; PUT may replace a prior goal association as HBB-16 specifies.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated client → goal/link API | Goal mutation and cross-resource link ids cross server authorization boundaries. |
| Goal API JSON → domain | Responses contain server-owned and extra fields that must not become unsupported UI behavior. |
| Habit selection → link/unlink sequence | User selection becomes multiple cross-resource mutations that can partially fail. |
| Dependency branch → final PR | Stacked history and shared router files can conceal scope contamination. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Elevation of Privilege | Link/unlink endpoints | mitigate | Offer habits from the authenticated repository, send only goal/habit ids, and rely on server ownership checks; never send usuarioId or treat the selector as authorization. |
| T-02-12 | Tampering | Goal status update | mitigate | Serialize only the documented enum and assert that status changes make zero habit lifecycle calls. |
| T-02-13 | Tampering | Multi-link mutation | mitigate | Diff current/selected ids, execute explicit PUT/DELETE operations, and reload authoritative goal/habit state after success or partial failure. |
| T-02-14 | Information Disclosure | Goal DTO/UI | mitigate | Map only allowed domain fields, ignore unrelated response keys, normalize API errors and expose no tokens or foreign resource details. |
| T-02-15 | Repudiation | Habit reassignment | mitigate | Display current assignment before save and reflect the server-returned association after PUT replacement semantics. |
| T-02-SC | Tampering | npm/pub supply chain | mitigate | Add no packages or lockfile changes; use the existing audited Flutter/Riverpod/Dio/Prism stack. |
</threat_model>
